Atomic Message Composition — execution board

Foundation → Parallel build → Serial mutation → Integrate & migrate

Foundation

Waves 1–2
ISSUE-1High

Expand Message and Attachment state

Depends on: none

Migration-safe fields, versioning, tombstones, ownership metadata, and private local storage.

Done when
  • Existing Messages remain readable.
  • Linked Attachments remain owned.
  • Private generated paths work.

Verify: migration tests, makemigrations --check, Django checks

ISSUE-2High

Deliver atomic creation and protected files

Depends on: ISSUE-1

Deep Message Composition interface, multipart creation, idempotency, validation, unread accounting, and authorized delivery.

Done when
  • Composition is all-or-nothing.
  • Retries create one Message.
  • Non-members cannot fetch files.
  • Live creation follows commit.

Verify: interface, DRF, Channels, and cleanup tests

Parallel build

Wave 3
ISSUE-3Medium

Move browser creation to HTTP

Depends on: ISSUE-2

One multipart request, stable retry key, draft preservation, canonical rendering, and live-event deduplication.

Done when
  • Messages render exactly once.
  • Failed drafts remain intact.
  • Attachments use protected URLs.

Verify: Vitest, browser creation test, production build

ISSUE-4High

Add atomic author-only editing

Depends on: ISSUE-2

Version-protected text and Attachment replacement with canonical responses and post-commit live updates.

Done when
  • Only current authors can edit.
  • Stale versions return conflict.
  • Failed edits preserve state.

Verify: interface, multipart PATCH, and Channels tests

Serial mutation

Wave 4
ISSUE-5High

Add invisible idempotent deletion

Depends on: ISSUE-2 · scheduled after ISSUE-4 to avoid overlap

Author-only deletion removes content and files, retains one internal tombstone, and broadcasts removal.

Done when
  • Deleted Messages vanish everywhere.
  • Tombstones never enter history.
  • Repeated deletion is stable.
  • Unread counts do not change.

Verify: deletion, privacy, cleanup, and event tests

Integrate & migrate

Waves 5–6
ISSUE-6High

Deliver browser edit and delete

Depends on: ISSUE-3, ISSUE-4, ISSUE-5

Author controls, conflict handling, invisible removal, and versioned cross-browser synchronization.

Done when
  • Only authors see controls.
  • Mutations synchronize once.
  • Older events cannot regress state.

Verify: Vitest and two-browser Playwright scenarios

ISSUE-7High

Retire legacy paths safely

Depends on: ISSUE-2 through ISSUE-6

Inventory and migrate data, remove JSON and orphan uploads, disable inbound WebSocket writes, and enforce final ownership.

Done when
  • Migration reports every count.
  • Linked files remain available.
  • Legacy writes are gone.
  • All test suites pass.

Verify: copied-data migration, Django, Vitest, build, Playwright, access check
